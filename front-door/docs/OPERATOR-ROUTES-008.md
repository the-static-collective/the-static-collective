# OPERATOR-ROUTES-008 — Get an actual job moving through existing machinery

**Draft staging implementation · 2026-10-30.** This is a local operator interface, not a server-side executor, agent, recipient manager, live service directory, or claim that the cross-repository stack is installed as a single runtime.

## Problem this solves

The human Porch serves an immediate need/offer/question with very little friction. However an operator with a practical objective—an application, food pilot, farm correspondence, music-film, work-group invitation, website repair, story, or source-native integration—needs a **short route to the already existing independently owned implementations**, not ten more layers of planning and duplicate application code.

### What genuinely executes in staging

- One `/work/` HTML application, independent of any login, backend or model.
- An **explicitly curated and reviewed** `/work/routes-v1.json` public source registry with 31 capabilities and eight task-focused journeys. Source URLs point to actual published documentation, PRs and known official release/prototype routes. Each resource declares its distinct state and limits. The registry itself has zero system authority.
- `work/router.mjs` validates the registry and human text, calls the **already existing local** `porch/next-move.mjs` engine, and compiles a small proposed work brief with source-owned evidence links and the particular human permission/field gate.
- The browser displays a few exact links worth opening. It does **not** automatically open or contact another system.
- The human can copy Markdown or save Markdown/JSON. The JSON schema `abundent/work-launch-card-v1` is **proposed-only** and expressly non-executable. It is *not* an accepted native JAR;VIS, reLATTE, planZ, BananaSpork or GRAFT contract.
- Only if requested, the operator can use the independent **already existing** `porch/interest-roads.mjs` selector to inspect JAR;VIS and planZ dated public context, using the same static local source snapshot. No text is sent as a network search query.

This is more than an index: it yields an actual reusable, job-specific artifact with permission gates and exact references. It is deliberately **not** a fake all-repo run.

## Source boundaries

- **Published binary:** Haunted Toaster's official Windows alpha is a concrete downloadable software artifact; unsigned binaries, input rights and release/licensing limitations still matter.
- **Source implementation:** GRAFT, reLATTE COMMUTER, BananaSpork and others have native code/CI and exact contracts; that is not proof of deployed human-facing services, field participants or actual benefit.
- **Backend deployed / review gated:** Garden Signal, Living Inbox, Workboard and Seven-Day Table have previously documented Supabase/provider paths. Each has its own identity, withdrawal, moderation and authorization. No automatic transfer of visitor details.
- **Draft experiments:** FIRST-INCH, Three Bells, TIMEBACK, Static Commons, CANNON, Storyship, grant and other PRs are not assumed to have been merged, released or independently field-tried.
- **Site readiness:** Switchboard has a configured alternative Vercel hostname, while `apps.abundent.org` presently has a reported DNS/hosting mismatch. Do not assume a configured host has passed an unauthenticated browser check.
- **Research sources:** JAR;VIS reviewed feed and planZ attention map are dated source indexes, not real-time availability or an authoritative identity graph.

## Tests and acceptance

```sh

node --test porch/*.test.mjs work/*.test.mjs
python -m unittest discover -s tests -v
python -m http.server 8080
```

Try each of the eight journeys without credentials, including mobile screen size, keyboard, copy and download, blocked input, missing invalid source file, and optional source lookup. GitHub CI has been extended to run **all** work and porch unit tests instead of only the oldest porch test. Keep the human Porch primary for strangers.

No secrets in this manifest or website. Avoid personal legal, family, survivor, health, contact or beneficiary details in portable cards. On shared devices exported files require operator custody.

## The genuine next source-owned integration

A separate source-owning `/operator/run` action could later accept an **explicitly reviewed** work brief, choose the source's real supported native interface, require a human approval gate, and return a cryptographically checked output from an isolated runner. That is intentionally *not implemented* by the static desk: this draft does not have the ability to execute original GitHub actions, send emails, mutate databases, render films, approve grants or dispatch volunteers.

Before adding any executor:
1. Choose one narrow original real module (for example source-native print proof from LemonPRESS, or a non-publishing GRAFT local kit).
2. Pin exact source SHA, action type and input/output schema; inspect dependencies/license.
3. Run original native tests **in the source owner**, then one cross-repository integration in CI against those pinned sources with a fictional fixture.
4. Require operator explicit execution consent and receiving owner permission; reject mismatched versions and secrets.
5. Return exact bytes, source commits, logs and honest failure; independent humans must still establish physical outcomes.

The goal is **one useful task actually finished faster**, not ten more orchestration names. Measure only voluntary observed time-to-artifact and field-confirmed utility, never minutes inferred from a code test.
